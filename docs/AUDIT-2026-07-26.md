# Mersal HBMP — Build Audit Report
**Date:** 2026-07-26 · **Scope:** security, code quality, backend↔frontend wiring, design-spec conformance
**Method:** four parallel code audits (evidence-based, file:line) against `HBMP-Design/` specs and the skills in `claude-code-skills/`
**Remediation:** every finding maps to a prompt in [`../HBMP-Design/claude-code-prompts/phase-16-audit-remediation.md`](../HBMP-Design/claude-code-prompts/phase-16-audit-remediation.md)

## 1. Executive summary

The build is **substantially real and unusually disciplined** — 19 services, ~700 tests, a genuine hash-chained + WORM audit spine, strict analyzers with zero suppressions or TODOs, DB-level idempotency, min-necessary test suites in 12 services, and a design system that matches the specs token-for-token. Phases 0–10, 10b, 14 (partially), and 15 are built; 11 is half-built; 11.3, 12, 13 are genuinely not started.

**But it is not production-safe yet.** Three critical/systemic gaps undermine the platform's own invariants:

1. **The "transactional outbox" is in-memory everywhere** (`useInMemory: true` in all 18 services) — audit and domain events are neither durable nor atomic with the DB commit. Invariant 3 (immutable audit on every mutation) does not survive a process restart.
2. **The defense-in-depth layers exist but are not engaged:** RLS is bypassed (all services connect as the superuser role; the GUC interceptor lives only in provider-service; most PHI services have no RLS at all), `FieldProjector` is used by zero services, break-glass grants never elevate anything at runtime (`NullBreakGlassProvider`), Kong performs no authentication, and admin-service's privileged endpoints have no authorization middleware (in-handler gate only — no scope, no MFA).
3. **The frontend and backend are not actually connected in live mode:** the default build is 100% fixtures with no env file to flip it; the SPA requests ~44 OAuth scopes while the realm defines 10 (live login fails); the call-centre portal has no realm role/scopes; the branch switcher calls a double-prefixed, unrouted URL; several endpoint groups (branches, practitioners, `/me`, report-access, examination-types, documents) have **no Kong route**; and three services claim `/api/v1/beneficiaries` while Kong routes it all to one.

There is also one **privacy hole against a stated hard rule**: the phase-14 sensitivity retrofit never reached approvals-service, so the medical-approval team can still read sensitive (mental-health) result content through the EMR oversight path — exactly what design doc 37 §6 forbids.

Finally, **test/CI integrity**: 165 DB-gated tests silently pass (not skip) when the DB env var is unset, and the CI test job has no database — so every concurrency/RLS/integration proof is green-by-default; the ≥80% coverage gate is an `echo`; CI is split across GitLab (stub) and GitHub Actions (partial).

**Verdict:** strong architecture and hygiene; the remaining work is largely *engaging what was built* (durability, RLS, projection, break-glass, gateway auth, live wiring) plus doc/CI truth-telling — not rebuilding features.

| Stream | Grade | One-liner |
|---|---|---|
| Security | **C+** | Excellent spine (audit/ClamAV/JWT/no-SQLi) but layered defenses not engaged; 1 committed credential |
| Code quality | **B+** | Exceptional discipline; test *integrity* (silent skips, coverage gate) is the weak spot |

## 4. Medium/low (bundled — full detail in the remediation prompts)

**Backend:** hardcoded `Password=hbmp` fallbacks (~14 files) + placeholder passwords in base appsettings; missing `Idempotency-Key` on admin/document/finance/reporting mutations; patient registration `PATCH` unaudited; masterdata has **no audit client** (screening endpoints infer clinical facts); bare `Results.NotFound()`/anonymous errors bypass problem+json (~7 services); ~14 near-identical `*Gate.cs` files (belongs in `libs/authz`); pharmacy sequence-table name interpolated into SQL (allowlist it); 8 services don't copy `Migrations/*.sql` to output; no shared migration runner (entity↔DDL drift undetectable); document/masterdata/policy/audit test suites thin vs their endpoints; eligibility event-consumer failure degrades silently to stale data (no health check); `services/hello` scaffold still in sln/compose/Kong.

**Frontend:** `HttpApiClient.ts` has 129 `any` + file-wide eslint-disable, zod schemas parsed at only 3 sites; **no ESLint config** (lint = `tsc --noEmit`); i18next installed but unused (bespoke per-file dictionaries; raw enum literals like `"BookAppointment"`, `"PatientUnwell"` render untranslated in Arabic); idempotency keys regenerated per submit (defeats retry safety); no `If-Match`/ETag/412 flow anywhere and Kong CORS wouldn't expose ETag anyway; `http.ts` discards problem+json bodies (one generic error for 401/403/409/422); RestrictedResultCard bypasses the design system with non-token hex colors + emoji; executive-dashboard finance filter (no diagnoses) exists **only in the fixture client**; finance exports hardcode a date window; CallCentre history swallows errors + fetches during render; reschedule declared but unimplemented; axe covers 3 shells not the flagship screens; no web Dockerfile/compose entry; 5 test files for 25 screens.

**Docs/status truth:** 10b marked ☐ ×9 but **fully built** (SHAs exist in HANDOFF); 11.1/11.2 substantially built but row says ☐; phase-14 dependency note written in future tense though 14 is ☑ (and incomplete per H4); ~20 commit placeholders + one SHA conflict; `HANDOFF.md` header/§2/§3/§9 stale by ~2 phases ("107 tests", document-service "PARTIAL"); no checked-in OpenAPI artifacts; ADRs missing for the 5 weightiest decisions (consume executor, hbmp_app RLS role, phase-14 retrofit, in-memory outbox interim, sensitive-result grants); `docs/runbooks/` doesn't exist (11.3 genuinely unstarted); master-data counts asserted nowhere.

## 5. What is genuinely good (keep it this way)

Audit spine is real: hash chain + verifier background service + MinIO WORM + triple-layer DB immutability, reads-of-audit audited. ClamAV fails closed; upload pipeline validates→checksums→scans→stores, every outcome audited. JWT validation strict (issuer/audience/lifetime/signed, raw claims). Zero SQL injection; zero TODO/FIXME; zero pragma suppressions; sanctioned NoWarn only; CPM + NuGetAudit(high) + deterministic builds. DB-level idempotency via UNIQUE keys in 7 schemas. Min-necessary is *tested* in 12 services (finance/claims-cannot-read-diagnosis, provider isolation + real 2-role RLS test, reception/queue min-necessary, orders sensitivity). Claims-service is the reference implementation (23 test files, 8 migrations, no-payment-path test). Frontend: strict TS, zod at the API boundary both directions, structural permission-gated routing with audited 403s, four-cue StatusChip with mandatory text, Radix focus management, four async states with correct live regions, tokens matching 0B + §10b v1.1 exactly, per-portal lazy code-split, real axe suites in CI for both packages. Provider-service is the template for isolation done right — most fixes are "do what provider did, everywhere."
